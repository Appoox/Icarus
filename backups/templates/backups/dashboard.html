{# ── Restoring ──────────────────────────────────────────────────── #}
How to restore

Restores run on the server, with restore.sh in the repository checkout. They work even when the site and its database are gone, and nothing on this page can start one: replacing the live database is not a web-button job.

  1. ./restore.sh list: the snapshots on Google Drive.
  2. ./restore.sh drill latest: restores the newest snapshot into a scratch database and checks it, touching nothing live. Worth doing every few months.
  3. ./restore.sh db latest (or a snapshot ID from the table): restores into a scratch database first, then stops the site, keeps a safety dump of the current database and swaps the restored one in. Downtime is the swap, not the restore.
  4. ./restore.sh media: copies back media files that are missing on the server; files already there are left alone.
  5. ./restore.sh env latest > .env.restored: the server's .env as of that snapshot.

Rebuilding a lost server from scratch is a numbered checklist in backups/README.md. It needs rclone.conf, so keep a copy of that file in your password manager: without its encryption passwords nobody, you included, can read the backups.
