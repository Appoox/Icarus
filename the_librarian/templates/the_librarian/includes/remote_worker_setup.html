{% comment %} Remote worker setup steps. Shown on the Remote Worker admin page and, as a panel, on the Remote Ingestion Worker Settings page. Needs the context from the_librarian.panels.remote_worker_setup_context. {% endcomment %}

The worker is a program you run on a computer of your choice, not on this server. It downloads the back issues that haven't been processed yet, reads the text off each page, and sends it back here so those issues become searchable. It runs on the processor, so no graphics card is needed.

1. Get a key and switch remote ingestion on

  1. {% if on_worker_page %}Under API Keys below{% else %}On the Remote Worker page (in the sidebar), under API Keys{% endif %}, type a label such as “Home workstation” and click + Generate Key. Copy the key straight away: it is shown only once. Give each computer its own key, so you can revoke one without stopping the others.
  2. Click Enable Remote Ingestion. While it is off, this site turns away every worker request, even ones with a valid key. It stays on until someone turns it off.

2. Install the worker (first time only)

You need a Linux or macOS computer with git, Python 3.10 or newer, and several gigabytes of free disk space for the text-recognition and search models. On Debian or Ubuntu, install the basics with sudo apt install git python3-venv. Then run: 

git clone {{ repository_url }}
cd Icarus/the_librarian/worker
LIBRARIAN_EMBEDDING_MODEL="{{ embedding_model }}" bash start.sh

The first run installs poppler (a PDF tool; it may ask for your password), creates a Python environment in .venv-worker and installs the worker's packages. This takes a while. After that, the worker starts straight away.

Start the worker with that last line every time. It tells the worker to use this site's search model, {{ embedding_model }}. With any other model, this site rejects what the worker sends.

Cloning needs read access to the Icarus repository. If the computer already has a checkout, run git pull in it instead of cloning again.

3. Run it

  1. start.sh opens the worker's control panel in your browser at http://127.0.0.1:5057. If no tab opens, go to that address yourself. Only that computer can reach this panel.
  2. In Icarus address, enter {{ site_base_url }}
  3. In Worker key, paste the key from step 1.
  4. Click Start processing. The worker's log shows each page as it goes, and {% if on_worker_page %}the counters below{% else %}the Remote Worker page{% endif %} show files downloaded and vectors uploaded. The first run also downloads the text-recognition and search models, so it is slow to get going.
  5. Click Stop whenever you like. Pages already read are kept in the worker's ocr_cache folder, so the next run picks up where this one stopped.

4. When you're finished

  • Click Disable Remote Ingestion{% if not on_worker_page %} on the Remote Worker page{% endif %}.
  • Close the worker by pressing Ctrl+C in its terminal window. Nothing keeps running afterwards.
  • If that computer won't run the worker again, revoke its key. Deleting its ocr_cache folder frees up the space.
Running it without a browser (on a server)

Install poppler first (sudo apt install poppler-utils, or brew install poppler on macOS). Then, from the cloned repository: 

cd Icarus/the_librarian/worker
python3 -m venv .venv-worker
.venv-worker/bin/pip install -r requirements-worker.txt
export ICARUS_BASE_URL="{{ site_base_url }}"
export ICARUS_WORKER_TOKEN="paste-your-key-here"
export LIBRARIAN_EMBEDDING_MODEL="{{ embedding_model }}"
.venv-worker/bin/python ingest_worker.py

If start.sh has already run on that computer, skip the venv and pip lines. Add --force to the last line to reprocess issues that were already done. The run stops by itself once nothing is left to process.

Troubleshooting
  • The log says a request was rejected: remote ingestion is switched off, or the key is mistyped or revoked. {% if on_worker_page %}Recent Activity below{% else %}The Recent Activity table on the Remote Worker page{% endif %} lists every rejected request and the reason.
  • The worker's log says “Failed on …” and Recent Activity says “embedding has … dimensions”: the worker was started without this site's search model. Stop it and start it again with the last line from step 2.
  • “0 issue(s) to process”: every issue has already been processed. Tick Reprocess everything in the worker to redo them.
  • The worker can't connect: check that the Icarus address is exactly {{ site_base_url }} and that the computer can open it in a browser.
  • Setup stopped with an error: run the last line from step 2 again; it retries the install. If it keeps failing, delete the .venv-worker folder and try once more.
