# worker/requirements-worker.txt
# ────────────────────────────────────────────────────────────────────────
# Dependencies for the standalone remote OCR/embedding worker
# (worker/ingest_worker.py). Installed on the worker machine only — this
# is the mirror image of production's requirements.txt, which drops these
# same heavy ML packages.
#
# NOT required: Django, Wagtail, psycopg2, pgvector-django, gunicorn/daphne,
# django-q2, channels — the worker never imports Django or touches Postgres
# directly. It only talks to production over HTTP.
#
# GPU note: if this machine has an NVIDIA GPU, install the matching CUDA
# build of torch FIRST (see https://pytorch.org/get-started/locally/)
# before running `pip install -r requirements-worker.txt` — otherwise pip
# will pull the default CPU wheel as a transitive dependency of
# sentence-transformers/ultralytics/surya-ocr below.

# ── Confirmed by direct imports in ingest_worker.py / text_cleanup.py ──
requests
pdf2image
regex
langchain-text-splitters
langchain-core
sentence-transformers<6   # 6.x needs transformers 5, which surya 0.17 can't load (see below)

# ── Needed only by worker_ui.py, the optional browser control panel.
#    Skip this line if you're only ever running ingest_worker.py from
#    the command line.
flask

# ── Imported by the_librarian/services/ocr_processing.py (surya) and
#    yolo_segmentation.py (ultralytics). Between them these also bring in
#    torch, opencv, numpy and Pillow. surya is pinned because
#    ocr_processing.py uses the 0.17 API: later releases removed
#    surya.foundation, so the worker would fail on startup. surya 0.17
#    also fails to load its model under transformers 5 ("SuryaDecoderConfig
#    object has no attribute pad_token_id"), so transformers is held to 4.x.
surya-ocr==0.17.1
transformers>=4.56.1,<5
ultralytics

# ── Also imported by ocr_processing.py, but not pulled in by either
#    package above — without them the worker fails on startup.
scikit-image
scipy
